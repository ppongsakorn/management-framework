# ซีรีส์ร้านอาหาร — Story Bible

กติกาของเจ้าของ (27 พ.ย. 2026): คลิปทุกตอนเป็น **เรื่องเดียวที่เดินไปข้างหน้า** ไม่ใช่คลิปสอน framework แยกกันที่บังเอิญใช้ร้านเดียวกัน เมื่อเจ้าของร้านแก้ปัญหาสำเร็จ ผลลัพธ์ต้องคงอยู่ในตอนถัดไป และปัญหาใหม่ต้องเกิดจากพัฒนาการของร้านอย่างสมเหตุสมผล

**แก่นเรื่อง:** การเติบโตของเจ้าของร้าน จากคนที่บริหารด้วยสัญชาตญาณ ไปสู่ผู้บริหารที่คิดอย่างเป็นระบบ ใช้ข้อมูลตัดสินใจ และสร้างธุรกิจที่เติบโตได้โดยไม่ต้องลงไปจัดการทุกเรื่องเอง ยึดแก่นนี้ไว้ ซีรีส์จะยาวกี่สิบตอนก็ยังเป็นเรื่องเดียวกัน

## Master Storyline

| ตอน | สถานการณ์ | สิ่งที่ค้นพบ | ผลลัพธ์และการส่งต่อ | สถานะ |
| --- | --- | --- | --- | --- |
| 1. 5 Whys | อาหารออกช้าวันเสาร์ เจ้าของร้านโทษพ่อครัว | ไม่มีขั้นตอนเช็กยอดจอง | เพิ่มขั้นตอนเช็กยอดจองทุกเช้า | ขึ้นเว็บแล้ว |
| 2. PDCA | มีวิธีแก้แล้ว แต่ยังไม่รู้ว่าได้ผลแค่ไหน | ต้องทดลองและวัดผล | เวลารอ 40 → 32 นาที ยังไม่ถึงเป้า 20 | ขึ้นเว็บแล้ว |
| 3. Fishbone | วันเสาร์ยังช้า ทีมเถียงกันว่าเพราะคนหรือเตา | หลายสาเหตุพันกัน | แก้ 3 สาเหตุที่ตรวจแล้ว (เตาใช้ได้ 2 จาก 3 หัว, ไม่เตรียมของเมนูขายดี, จับเวลาแค่ตอนสั่ง) จนเวลารอถึงเป้า 20 นาที | ขึ้นเว็บแล้ว |
| 4. Pareto 80/20 | อยากลดเวลารอลงอีก แต่ทรัพยากรจำกัด | 3 จาก 8 เรื่อง = 80% ของเวลาที่เสีย (1,000 นาทีต่อเดือน) | ลงแรงกับเตรียมวัตถุดิบ, ลำดับการใช้เตา, ตรวจออร์เดอร์ | ขึ้นเว็บแล้ว |
| 5. Theory of Constraints | บริการดีขึ้น ลูกค้ามากขึ้น เพิ่มพนักงานเสิร์ฟแล้วอาหารออกได้เท่าเดิม | เตาคือคอขวดของทั้งระบบ | รีดเตา → ให้ทุกขั้นเดินตามจังหวะเตา → เพิ่มเตาหัวที่ 4 → คอขวดย้ายไปที่การล้างจาน | ขึ้นเว็บแล้ว |
| 6. Eisenhower Matrix | ร้านโตขึ้น เจ้าของร้านมีภาระงานมากขึ้น | ใช้เวลาส่วนใหญ่กับงานด่วนจนละเลยงานสำคัญ | จัดลำดับงาน มอบหมาย บริหารเวลาเป็นระบบ (ได้คนล้างจานเพิ่ม 1 คน) | ขึ้นเว็บแล้ว |
| 7. Delegation Levels | มอบหมายแล้ว แต่พนักงานยังเดินมาถามเจ้าของร้านทั้งวัน | คอขวดย้ายมาอยู่ที่ตัวเจ้าของร้าน: ไม่ชัดว่าใครตัดสินใจได้แค่ไหน | ตกลงระดับการตัดสินใจ 7 ระดับต่อเรื่อง พร้อมขอบเขตงบ โทรศัพท์เงียบลง แต่วัตถุดิบมาไม่ถึงร้าน | ขึ้นเว็บแล้ว |
| 8. RACI | วันเสาร์วัตถุดิบหลักไม่มา หัวหน้าครัวกับฝ่ายจัดซื้อต่างคิดว่าอีกคนสั่งแล้ว | งานสั่งวัตถุดิบไม่มี A, งานจัดตารางมี A 3 คน | ทุกงานมี A คนเดียว วันเสาร์ถัดมาวัตถุดิบมาครบตรงเวลา | ขึ้นเว็บแล้ว |
| 9. Skill / Will Matrix | หน้าที่ชัดแล้ว แต่บางคนผิดบ่อย บางคนไม่อยากรับงานเพิ่ม | คนต่างกันต้องการการสนับสนุนต่างกัน | สอนพนักงานใหม่, คุยหาสาเหตุกับพนักงานเก่า, ให้อำนาจหัวหน้าครัว; ส่งต่อ Situational Leadership (ตอน 10) | ขึ้นเว็บแล้ว |
| 10. Situational Leadership | เจ้าของร้านสอนหัวหน้าครัวทีละขั้น จนได้คำตอบว่า "ผมทำงานนี้มาสิบปีแล้ว" | ไม่มีวิธีบริหารแบบเดียว: ปรับการชี้แนะ × การสนับสนุนตามความพร้อมในงานนั้น | พนักงานใหม่ทำงานได้เอง หัวหน้าครัวปรับระบบได้อิสระ หัวหน้าร้านดูแลทีมแทน แต่เจ้าของร้านยังต้องเดินถามความคืบหน้าทั้งวัน; ส่งต่อ Kanban (ตอน 11) | ขึ้นเว็บแล้ว |
| 11. Kanban | ทุกคนบอกว่า "กำลังทำ" แต่ไม่มีอะไรเสร็จ | บนกระดานมีงานกำลังทำ 12 งาน เสร็จ 0: ทุกคนสลับงานไปมา | กระดาน 4 ช่อง + WIP ≤ 3 + ดึงงาน + Blocked + นิยามคำว่าเสร็จ ทีมส่งงานเสร็จต่อเนื่อง แต่หนึ่งเดือนต่อมาลูกค้าซื้อซ้ำและกำไรยังไม่ดีขึ้น; ส่งต่อ OKR (ตอน 12) | ขึ้นเว็บแล้ว |
| 12. OKR | งานเสร็จ 20 เรื่องในเดือนเดียว แต่ลูกค้าซื้อซ้ำน้อยและกำไรแทบไม่เพิ่ม | งานเสร็จ ≠ เข้าใกล้เป้าหมาย (Output ≠ Outcome) | ตั้ง Objective + 3 KR ทบทวนทุกสัปดาห์ ปรับแผนเมื่อเจอว่ารสชาติไม่สม่ำเสมอ ครบไตรมาส KR1 43/45%, KR2 96/95%, KR3 15/16%; ร้านมีลูกค้าประจำ อยากเปิดสาขาสอง ส่งต่อ SWOT (ตอน 13) | ขึ้นเว็บแล้ว |
| 13. SWOT | ร้านขายดี เจ้าของร้านฝันเปิดสิบสาขา ทีมถามว่าใครดูแลครัวใหม่ หาลูกค้าจากไหน | ร้านเดียวรอด ≠ ขยายแล้วรอด; ครบสี่ช่องยังไม่ใช่กลยุทธ์ ต้องจับคู่ | ลองขายชุดกลางวันก่อน ฝึกหัวหน้าครัวคนใหม่ เลือกร้านเล็ก หรือชะลอ เช็ก 3 เรื่องก่อน ยังไม่เซ็นสัญญาเช่า; ส่งต่อ Porter's 5 Forces (ตอน 14) | ขึ้นเว็บแล้ว |
| 14. Porter's 5 Forces | ไปดูทำเลสาขาสอง เจอคู่แข่ง 5 ร้าน ซัพพลายเออร์ขึ้นราคา ลูกค้าเทียบราคาในแอป | ห้าแรงกดดันสูงเกือบทุกด้าน: ตลาดขายดี ≠ ทำกำไรดี | โตได้โดยไม่ต้องเปิดสาขา: ชุดกลางวันให้ออฟฟิศ ขายลูกค้าเดิมเพิ่ม; ส่งต่อ Ansoff Matrix (ตอน 15) | ขึ้นเว็บแล้ว |
| 15. Ansoff Matrix | ถ้าไม่เช่าที่ใหม่ ร้านจะโตยังไง (ยังไม่เซ็นสัญญา) | โตได้หลายทาง: สินค้าเดิม/ใหม่ × ตลาดเดิม/ใหม่ ยิ่งมีส่วนที่ใหม่ ยิ่งต้องพิสูจน์มาก | ไอเดีย 4 ช่อง: เปิดให้จองอาหารเดิมล่วงหน้า / ชุดมื้อด่วน / ส่งอาหารเดิมให้คนย่านสำนักงาน / ชุดอาหารพร้อมปรุง พักช่อง 4 เหลือ 3 ทาง; ส่งต่อ Weighted Decision Matrix (ตอน 16) | รอตรวจบน dev |
| 16. Weighted Decision Matrix | เหลือไอเดียโตสามใบ ครัวอยากเหลือกำไร หน้าร้านอยากได้ลูกค้าใหม่ ต่างคนต่างบอกว่าของตัวเองชนะ | ต้องตกลงเกณฑ์และน้ำหนักก่อนเถียงคะแนน อันดับไวต่อสมมติฐาน | เกณฑ์ 4 ข้อ น้ำหนัก 40/30/20/10 คะแนนเฉลี่ยสมมติ 3.3 / 3.1 / 3.0 ลดกำไรของจองล่วงหน้า 4→3 เหลือ 2.9 ชุดมื้อด่วนนำ ทีมทดลองรับจองวงเล็ก; ส่งต่อ Pre-mortem (ตอน 17) | รอตรวจบน dev |
| 17. Pre-mortem | จะเปิดรับจอง นิ้วค้างเหนือปุ่ม หัวหน้าครัวชวนสมมติว่าอีกหกเดือนเลิกไปแล้ว | แต่ละคนเห็นความเสี่ยงคนละมุม: จองไม่มารับ / รับพร้อมกันจนโต๊ะรอ / ราคาวัตถุดิบขึ้น | เขียนเงียบ วนอ่าน โหวต 3 ข้อ ทุกข้อมีเจ้าของและสิ่งที่ทำได้ทันที ตารางวันแรกยังว่าง (ยังไม่มีผลทดลอง ยังไม่กำหนดตอน 18) | รอตรวจบน dev |

## พัฒนาการของเจ้าของร้าน

| ตอน | จาก | เป็น |
| --- | --- | --- |
| 1. 5 Whys | คนที่ชอบโทษคน | คนที่ค้นหาสาเหตุ |
| 2. PDCA | คนที่แก้ปัญหาตามความรู้สึก | คนที่ทดลองและวัดผล |
| 3. Fishbone | คนที่มองปัญหาด้านเดียว | คนที่มองปัญหารอบด้าน |
| 4. Pareto 80/20 | คนที่พยายามแก้ทุกเรื่อง | คนที่เลือกแก้เรื่องสำคัญ |
| 5. TOC | คนที่ปรับปรุงทีละจุด | คนที่มองประสิทธิภาพทั้งระบบ |
| 6. Eisenhower | คนที่คอยวิ่งดับไฟ | ผู้บริหารที่รู้จักใช้เวลาและทรัพยากร |
| 7. Delegation Levels | คนที่ต้องตัดสินใจทุกเรื่องเอง | คนที่กระจายอำนาจตัดสินใจอย่างมีขอบเขต |
| 8. RACI | คนที่คิดว่าทุกคนรู้หน้าที่ | คนที่ทำให้ความรับผิดชอบชัดเจน |
| 9. Skill / Will | คนที่ใช้วิธีเดียวกับทุกคน | ผู้นำที่ปรับการสนับสนุนตามแต่ละคน |
| 10. Situational Leadership | คนที่ช่วยทุกคนด้วยวิธีเดียว | ผู้นำที่ปรับวิธีตามความพร้อมของคนในงานนั้น |
| 11. Kanban | คนที่เดินถามความคืบหน้าทีละคน | คนที่ทำให้ทุกคนเห็นงานร่วมกันและปิดงานให้เสร็จ |
| 12. OKR | คนที่นับงานที่เสร็จ | คนที่วัดผลลัพธ์และพาทีมไปเป้าหมายเดียวกัน |
| 13. SWOT | คนที่มั่นใจจากความสำเร็จเดิม | คนที่เข้าใจทั้งจุดแข็ง จุดอ่อน โอกาส และความเสี่ยงก่อนลงทุน |
| 14. Porter's 5 Forces | คนที่มองแค่ว่าตลาดมีลูกค้าเยอะ | คนที่ดูว่าใครกดดันกำไร และเห็นว่าการโตมีหลายทาง |
| 15. Ansoff Matrix | คนที่คิดว่าโต = ต้องเปิดสาขาใหม่ | คนที่แยกส่วนที่คุ้นเคยออกจากส่วนที่ยังต้องพิสูจน์ก่อนลงทุน |
| 16. Weighted Decision Matrix | คนที่ชนะด้วยเสียงดังหรือความรู้สึก | คนที่ตกลงเกณฑ์และน้ำหนักก่อน แล้วทดสอบว่าอันดับไวต่อสมมติฐานไหน |
| 17. Pre-mortem | คนที่มั่นใจก่อนเปิดตัว | คนที่ให้ทีมจินตนาการว่าพังไปแล้ว แล้วให้ทุกความเสี่ยงมีเจ้าของ |

## กติกาความต่อเนื่อง

- **Character Continuity:** ตัวละครจำและใช้สิ่งที่เรียนรู้จากตอนก่อน (เช่น หลังตอน Pareto เจ้าของร้านตัดสินใจด้วยตัวเลข ไม่จ้างคนเพิ่มแบบไม่มีเหตุผล)
- **Problem Continuity:** ปัญหาใหม่ต้องมีที่มาจากเหตุการณ์หรือผลลัพธ์ของตอนก่อน
- **Data Continuity:** ตัวเลข จำนวนพนักงาน อุปกรณ์ และผลการปรับปรุงต้องสอดคล้องกัน (ดูข้อเท็จจริงกลางด้านล่าง)
- **Framework Accuracy:** framework ทำหน้าที่ตามหลักการจริง ไม่บิดทฤษฎีให้เข้ากับเรื่อง ขั้นตอนตรงกับ `steps` ใน `data/frameworks.json`
- **Knowledge Accumulation:** framework ใหม่เสริมเครื่องมือเดิม ไม่แทนที่
- **Standalone Episode:** คนที่ไม่เคยดูตอนก่อนต้องเข้าใจได้ (ท้าวความสั้น ๆ ในฉาก recap)
- **Tone Consistency:** ภาษาพูดธรรมชาติ สนุก มีอารมณ์ขัน มีจุดพลิก ไม่เหมือนอ่านตำรา
- **Website Consistency:** บทพากย์ ตัวอย่าง (`exampleSteps`) แผนภาพ และตัวเลขบนเว็บใช้ข้อมูลชุดเดียวกัน
- **ส่งต่อทุกตอน:** ตอนจบชวนไปตอนถัดไปตาม Master Storyline

## ข้อเท็จจริงกลาง (canon)

ทุกตอนและทุกตัวอย่างบนเว็บต้องไม่ขัดกับรายการนี้ เพิ่มแถวเมื่อตอนใหม่สร้างข้อเท็จจริงใหม่

| เรื่อง | ค่า | ตั้งแต่ตอน |
| --- | --- | --- |
| ร้าน | ร้านอาหารสมมติ ไม่มีชื่อ ไม่ใช้ชื่อร้านหรือแบรนด์จริง | 1 |
| ตัวเอก | เจ้าของร้าน (ตั้งแต่ตอน 2 เป็นคนบริหาร ไม่ใช่นักสืบ) | 1–2 |
| ตัวละครอื่น | พ่อครัว, หัวหน้าครัว, พนักงานเสิร์ฟ, แคชเชียร์, คนล้างจาน | 1, 3 |
| วันที่มีปัญหา | วันเสาร์ (ยอดจองสูง) | 1 |
| ขั้นตอนที่เพิ่มแล้ว | หัวหน้าครัวเช็กยอดจองทุกเช้าแล้วเตรียมของตามนั้น (เป็นมาตรฐานตั้งแต่ตอน 2) | 1–2 |
| เวลารออาหารวันเสาร์ | 40 → 32 นาที (ตอน 2) → ≤ 20 นาที ถึงเป้า (ตอน 3) | 2–3 |
| เตา | 3 หัว; ตอน 3 ใช้ได้แค่ 2 แล้วซ่อมครบ 3; ตอน 5 เพิ่มหัวที่ 4 | 3, 5 |
| เวลาที่เสียต่อเดือน (ตอน 4) | 1,000 นาที: เตรียมวัตถุดิบไม่ทัน 380 / รอใช้เตา 250 / ออร์เดอร์ผิด 170 / อีก 5 เรื่อง 200 (รอจานสะอาด 80, รอคนยกเสิร์ฟ 60, อื่น 60) | 4 |
| คนล้างจาน | ตอน 3 "ไม่พอ" แต่ไม่ได้ถูกเลือกแก้; ตอน 4 "รอจานสะอาด" 8%; ตอน 5 กลายเป็นคอขวดใหม่ (75 จาน/ชม.); ตอน 6 จ้างเพิ่ม 1 คน | 3–6 |

## จุดที่ยังไม่ต่อเนื่อง (ตรวจจากไฟล์จริง 27 พ.ย. 2026)

1. **PDCA ภาพไม่ตรงเสียง:** เสียงพากย์และตัวอย่างบนเว็บบอก "ลองแค่ 2 วันเสาร์" แต่ภาพในคลิปเป็นตาราง "วันเสาร์ 4 ครั้ง" แก้ได้ด้วยการเรนเดอร์ภาพใหม่ ไม่ต้องอัดเสียง
2. **Pareto ต่อจาก Fishbone:** ตอน 3 แก้ "เตาใช้ได้ 2 จาก 3 หัว" และ "ไม่เตรียมของเมนูขายดี" ไปแล้ว แต่ตอน 4 อันดับ 1–2 ยังเป็นเรื่องวัตถุดิบและเตา อธิบายได้ว่าเตาครบ 3 หัวแล้วก็ยังเป็นจุดที่ต้องต่อคิว (ซึ่งเป็นเหตุของตอน 5) ควรใส่ประโยคนี้ในตัวอย่างบนเว็บของ Pareto
3. **Pareto ยังไม่ส่งต่อ:** คลิปตอน 4 จบด้วยการสรุปซีรีส์ ไม่มีการ์ด "ตอนหน้า" ใส่การ์ด "ตอนหน้า: Theory of Constraints" ในฉากสุดท้ายได้โดยไม่ต้องอัดเสียงใหม่
